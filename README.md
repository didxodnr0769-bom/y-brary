# YBrary

프로젝트, 책, 강의 기록과 학습 정리를 한곳에서 보여주는 개인 아카이브입니다. 방문자는 목록을 검색하고 최신순으로 탐색하며, 각 항목의 상세 기록을 읽을 수 있습니다.

현재 앱은 저장소의 정적 콘텐츠를 빌드에 포함합니다. 등록된 프로젝트와 책 기록은 유지하며, 강의 기록과 학습 정리는 빈 목록에서 시작합니다. 실제 사용자 기록을 확인하지 않은 샘플은 추가하지 않습니다.

## 기술 구성

- React 19, TypeScript, Vite 기반의 정적 SPA
- React Router의 브라우저 라우팅과 정적 호스트용 경로별 HTML 셸
- Tailwind CSS 4 기반의 반응형 라이트·다크 테마
- 정적 TypeScript 콘텐츠, 공통 Markdown 상세 본문과 Zod 검증
- 기존 Supabase Postgres, Storage, RLS 전환 준비물(현재 앱에서 미사용)
- Zod 콘텐츠 검증, Sharp 이미지 WebP 최적화
- Vitest, ESLint, TypeScript 검사

## 시작하기

Node.js 24 LTS와 pnpm 11을 사용합니다.

```bash
corepack enable
pnpm install
pnpm dev
```

브라우저에서 `http://localhost:3001`을 엽니다. 프로젝트·책·강의는 `src/lib/content/static-data.ts`, 학습 정리는 `content/notes/*.md`에서 관리합니다.

## 환경 변수

| 이름 | 용도 |
| --- | --- |
| `VITE_SITE_URL` | 사이트 메타데이터 기준 URL. 기본값 `http://localhost:3001` |
| `VITE_BASE_PATH` | 앱과 배포 자산의 기준 경로. 기본값 `/`, 저장소 Pages 예시 `/y-brary/` |
| `VITE_ENABLE_INDEXING` | `true`일 때만 검색 엔진 색인 허용 |
| `NEXT_PUBLIC_SUPABASE_URL` | 향후 Supabase 게시 스크립트가 사용할 URL |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | 향후 Supabase 연동에 사용할 공개 키 |
| `SUPABASE_SECRET_KEY` | 게시 스크립트 전용 비밀키. 클라이언트 코드에 사용 금지 |
| `SUPABASE_MEDIA_BUCKET` | 공개 이미지 버킷 이름. 기본값 `media` |

`VITE_*` 변수는 공개 빌드 설정이므로 비밀키를 넣지 않습니다. 현재 앱 런타임은 Supabase 환경 변수를 읽지 않습니다. 위 Supabase 변수는 기존 데이터베이스 전환 준비물과 원격 게시 도구를 위한 예약 설정입니다. 해당 도구의 기존 `book`/`film` 계약은 현재 앱의 강의 기록·학습 정리 계약으로 전환하지 않았습니다.

## 정적 콘텐츠 관리

프로젝트, 책, 강의 기록은 `src/lib/content/static-data.ts`에서, 학습 정리는 `content/notes/*.md`에서 관리합니다. 학습 정리 파일은 YAML frontmatter에 메타데이터를 두고 그 아래에 Markdown 본문을 작성합니다. 스키마에 맞지 않는 데이터는 빌드 전에 Zod 검증에서 실패합니다. 프로젝트·강의 이미지가 아직 없다면 임의 이미지로 채우지 않고 화면에 미첨부 안내를 표시합니다. 학습 정리는 별점 없이 제목, 정리일, 요약, 본문, 태그로 구성하며, 이해를 돕는 설명 이미지를 본문에 대체 텍스트와 함께 첨부할 수 있습니다.

- `/`: 기록과 주제의 연결을 탐색하는 그래프 홈
- `/projects`: 프로젝트 목록
- `/books`: 책 기록
- `/courses`: 강의 기록
- `/notes`: 학습 정리

각 목록에서 `/projects/:slug`, `/books/:slug`, `/courses/:slug`, `/notes/:slug`의 상세 기록으로 이동할 수 있습니다. 검색은 브라우저에서 처리합니다. 영화 목록과 상세 화면은 제공하지 않습니다.

전용 목록과 상세 화면은 어두운 상단 내비게이션·소개 영역과 밝은 콘텐츠, 주황색 포인트를 조합한 스플릿 콘트라스트 디자인을 사용합니다. 제목·본문·브랜드·코드 표시를 메이플스토리 서체로 통일하며 라이트·다크 테마를 지원합니다. 모바일에서는 상단 버튼으로 메뉴를 펼칠 수 있습니다.

홈은 전역 헤더 아래의 화면 전체를 어두운 그래프 캔버스로 채웁니다. 중앙에는 다른 노드보다 큰 따뜻한 흰색 별 ‘나’를 두고, 주변에 네 기본 분류의 별자리를 비대칭으로 배치합니다. 주황색 분류·주제와 밝은 기록을 가는 선으로 연결하고, 배경에는 연결선이 없는 작은 별을 배치합니다. 소개 문구·목차·분류별 미리보기·최근 기록 목록을 두지 않으며, 기본 화면에는 ‘나’와 분류·주요 주제·일부 기록의 이름만 표시합니다.

그래프에는 프로젝트·책·강의 기록·학습 정리의 기본 분류 노드를 항상 표시하고, 각 작성글을 해당 분류에 자동으로 연결합니다. ‘나’는 네 기본 분류에만 가는 선으로 연결하며, 이 구조 연결은 작성글 수에 포함하지 않습니다. 글이 없는 분류도 노드는 유지하며 예시 글을 채우지 않습니다. 여기에 실제 프로젝트·학습 태그와 책 카테고리를 주제로 연결하며 같은 기록의 중복 태그는 한 번만 연결합니다. 태그가 없는 글도 해당 기본 분류에 연결됩니다. 강의 플랫폼이나 본문에서 관계를 추정하지 않고, 데이터가 많아진 시안에 사용한 예시 기록도 앱에 추가하지 않습니다. 분류나 주제를 선택하면 연결된 기록을 강조하고, 기록을 클릭하거나 Enter를 누르면 해당 상세 화면으로 이동합니다. 기록 이름은 포인터를 올리거나 키보드 초점을 옮겨 확인할 수 있습니다. ‘나’에 포인터나 초점을 옮기면 네 분류 연결을 강조하고, 클릭하거나 Enter·Space를 누르면 `kind`·`tag` 선택을 해제하고 검색 조건 `q`를 유지한 채 전체 구도로 돌아갑니다.

드래그와 방향키로 그래프를 이동하고 휠·확대/축소 버튼으로 크기를 조절하며, 전체 보기 버튼으로 처음 구도를 복원합니다. 분류나 주제를 선택하면 직접 연결된 기록이 화면에 들어오도록 중앙을 맞추고 최대 4배까지 확대하며, 선택 해제는 강조만 없애고 전체 보기 버튼 또는 0키로 전체 구도를 복원합니다. 모바일은 터치 이동과 두 손가락 확대/축소를 지원합니다. 기존 홈의 `q` 주소는 기록 검색 조건으로 유지하며, `kind`는 기본 분류를, `tag`는 주제를 선택한 상태로 엽니다. 그래프 캔버스는 테마 선택과 관계없이 어두운 배경을 사용하며, 홈의 서체 저작권 안내는 캔버스의 보조 링크로 접근합니다.

검색은 전용 목록에서 사용합니다. 상단 검색 버튼은 목록에서 검색 입력에 초점을 옮기고, 상세 화면에서는 같은 종류의 목록으로 이동한 뒤 입력에 초점을 옮깁니다. 홈에는 검색 입력과 상단 검색 버튼을 표시하지 않습니다. 프로젝트 목록은 검색창 아래에 빈도순 태그와 기록 수를 표시하며, 태그 필터와 검색어를 함께 사용할 수 있습니다. 책 목록은 제목 또는 저자로 검색하고 카테고리 선택과 빈도순 카테고리 태그로 좁혀 봅니다.

세로형 책 표지는 잘리지 않도록 전체를 맞추고 여백을 둡니다. 책 전용 목록은 완독일 기준으로 정렬하며 데스크톱 4열·태블릿 3열·모바일 2열로 표시합니다.

### 상세 본문 작성

프로젝트의 `description`, 책·강의의 `body`, 학습 정리의 본문은 모두 Markdown으로 표시합니다. 제목, 한 줄 요약과 메타데이터는 일반 텍스트로 작성합니다. 프로젝트·책·강의 본문은 `static-data.ts`의 여러 줄 문자열에, 학습 정리 본문은 `.md` 파일에 작성합니다.

소제목, 강조, 목록, 인용문, 링크, 코드 블록과 함께 표, 체크리스트, `~~취소선~~`을 지원합니다. `4~5월`처럼 단일 물결표는 그대로 표시하며, HTML 태그는 지원하지 않습니다.

```markdown
## 주요 내용

본문은 빈 줄로 문단을 나눕니다. **강조할 내용**도 표시할 수 있습니다.

- 첫 번째 항목
- 두 번째 항목

> 인상 깊었던 문장
```

단일 줄바꿈은 같은 문단으로 이어집니다. 문단 안에서 명시적으로 줄을 바꾸려면 줄 끝에 공백 두 개 또는 역슬래시를 사용합니다. TypeScript 여러 줄 문자열 안의 백틱과 역슬래시는 문자열 이스케이프 규칙에 맞춰 작성합니다. 기존 글을 정돈할 때는 원문과 메타데이터를 유지하고 서식만 적용합니다.

## 정적 배포

`pnpm build`는 `dist/`에 배포 파일을 생성합니다. 저장소의 하위 경로로 배포할 때는 빌드 기준 경로를 지정합니다.

```bash
VITE_BASE_PATH=/y-brary/ pnpm build
VITE_BASE_PATH=/y-brary/ pnpm preview
```

프로덕션 사이트 주소는 빌드 전에 `VITE_SITE_URL`로 설정합니다. 빌드는 목록과 등록된 상세 경로마다 `index.html` 셸을 복사하고 `404.html`을 생성합니다. GitHub Pages에서 유효한 상세 주소를 직접 열거나 새로고침해도 앱을 불러올 수 있습니다. 각 셸의 콘텐츠 본문은 브라우저의 React가 렌더링하며, 페이지별 본문 HTML을 미리 만드는 SSG나 검색 엔진용 프리렌더링은 구현하지 않습니다.

GitHub Pages 배포는 `main` 브랜치에 push하면 `.github/workflows/deploy-pages.yml`이 자동 실행됩니다. GitHub Actions의 `Run workflow`로 수동 실행할 수도 있습니다. 워크플로는 Node.js 24와 pnpm 11로 의존성을 설치하고 린트·타입 검사·테스트·빌드가 통과하면 `dist/`만 게시합니다. 저장소 경로는 `/y-brary/`이며 검색 엔진 색인은 기본적으로 차단합니다. 공개 콘텐츠는 정확한 미리보기에 명시적 승인을 받은 뒤 `main`에 push합니다. 실제 Pages 활성화도 대상과 승인을 확인한 뒤 진행합니다.

## 기존 원격 게시 도구

아래 명령은 기존 Supabase 원격 게시 도구입니다. 현재 정적 앱 콘텐츠를 변경하지 않으며, 강의 기록·학습 정리는 지원하지 않습니다.

```bash
pnpm content:preview content/drafts/example.json
pnpm content:publish content/drafts/example.json --approved
```

원격 게시 명령은 게시할 정확한 콘텐츠의 미리보기와 사용자 승인을 마친 뒤에만 실행합니다. 원본 이미지를 WebP로 최적화해 Storage에 올리고, 서비스 역할만 실행할 수 있는 RPC로 콘텐츠를 반영합니다. 자세한 절차는 [콘텐츠 게시 가이드](docs/content-publishing.md)를 참고하세요.

## 기존 Supabase 로컬 개발 준비물

Docker가 실행 중인 환경에서 다음 순서로 로컬 스키마를 재현합니다.

```bash
pnpm exec supabase start
pnpm exec supabase db reset
pnpm exec supabase status
```

기존 스키마는 프로젝트와 책·영화 리뷰를 대상으로 하며 강의 기록·학습 정리는 포함하지 않습니다. 초기 마이그레이션은 공개된 콘텐츠의 `SELECT`만 `anon`과 `authenticated` 역할에 허용합니다. 테이블 쓰기와 게시 RPC는 `service_role` 전용이며, 공개 `media` 버킷도 클라이언트 업로드 정책을 만들지 않습니다.

원격 YBrary Supabase 프로젝트 생성과 마이그레이션 적용은 아직 자동으로 수행하지 않습니다. 비용·조직 선택이 필요한 외부 변경이므로 대상 프로젝트를 정한 뒤 별도로 연결해야 합니다.
