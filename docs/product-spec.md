# YBrary 제품 명세

## 목적

YBrary는 개인 사이드 프로젝트와 책·영화 감상 기록을 하나의 공개 아카이브로 정리한다. 프로젝트는 결과물을 빠르게 보여주고, 책과 영화는 감상 사실과 짧은 평가에서 상세 기록으로 자연스럽게 이어지게 한다.

## 정보 구조

| 경로 | 역할 |
| --- | --- |
| `/` | 프로젝트 목록, 제목·태그 검색, 최신순 정렬 |
| `/projects/[slug]` | 프로젝트 설명, 이미지, GitHub·서비스 링크 |
| `/books` | 책 목록, 제목 검색, 감상일 최신순 정렬 |
| `/books/[slug]` | 책 정보, 별점, 한 줄 감상, 상세 감상 |
| `/films` | 영화 목록, 제목 검색, 감상일 최신순 정렬 |
| `/films/[slug]` | 영화 정보, 별점, 한 줄 감상, 상세 감상 |

데스크톱은 고정 사이드바, 모바일은 상단 헤더와 열고 닫는 내비게이션을 사용한다. 테마는 시스템 설정을 초기값으로 삼고 사용자의 선택을 브라우저에 저장한다.

## 콘텐츠 계약

### 프로젝트

- 영문 소문자·숫자·하이픈으로 구성된 고유 slug
- 제목 120자, 한 줄 설명 300자, 상세 설명 2,000자 이내
- 선택적인 썸네일 1개와 스크린샷 0~6개. 이미지가 있으면 대체 텍스트 필수
- 이미지가 아직 없으면 목록과 상세 화면에 미첨부 안내 표시
- 선택적인 GitHub URL과 서비스 URL
- 프로젝트 성격을 나타내는 태그 0~8개
- 선택적인 프로젝트 시작일과 종료일. 확인된 경우 화면에 진행 기간으로 표시
- 공개 시각과 생성·수정 시각

### 책·영화 리뷰

- `book` 또는 `film` 종류와 고유 slug
- 제목과 저자·감독, 감상일
- 0.5~5.0 범위의 0.5 단위 별점
- 한 줄 감상 300자, 상세 감상 2,000자 이내
- 표지·포스터 이미지와 대체 텍스트
- 공개 시각과 생성·수정 시각

## 데이터 및 공개 정책

- 현재 앱은 `src/lib/content/static-data.ts`의 정적 콘텐츠만 읽는다.
- 샘플 레코드는 앱에 포함하지 않는다.
- 정적 콘텐츠는 Zod 스키마를 통과해야 빌드할 수 있다.
- 이미지 원본과 공개 권리를 확인한 뒤 배포 자산에 추가한다.
- Supabase 스키마와 게시 도구는 향후 데이터베이스 전환을 위한 준비물이며 현재 앱 런타임에서는 사용하지 않는다.
- 검색 엔진 색인은 `ENABLE_INDEXING=true`로 명시하기 전까지 차단한다.

## 콘텐츠 운영 원칙

- 사용자에게 확인받지 않은 개인 프로젝트·감상 사실을 만들어 게시하지 않는다.
- 영화 포스터, 책 표지, 프로젝트 스크린샷은 공개 사용 권한과 출처를 확인한다.
- 게시 전 `content:preview` 결과를 사용자에게 보여주고 명시적인 승인을 받는다.
- 원본 이미지와 draft는 로컬 작업물이며, 배포 자산에는 최적화된 WebP만 사용한다.

## 현재 범위 밖

- 방문자 회원가입, 댓글, 좋아요
- 브라우저 기반 관리자 화면과 직접 편집
- 상세 설명 전문 검색과 추천
- 자동 배포 및 원격 Supabase 프로젝트 자동 생성

## 남은 외부 결정

- 데이터베이스 전환이 필요해지는 시점과 Supabase 조직·요금제·프로젝트 리전
- 배포 호스트와 운영 도메인
- 실제 첫 책·영화 기록과 YBrary 프로젝트 이미지
- 검색 엔진 색인을 켤 시점
