# YBrary 제품 명세

## 목적

YBrary는 개인 사이드 프로젝트, 책과 강의 기록, 배움과 생각을 하나의 공개 아카이브로 정리한다. 프로젝트는 결과물을 빠르게 보여주고, 책과 강의는 경험과 평가를 남기며, 노트는 배운 내용과 개인적인 생각, 대화를 통해 정리한 관점을 태그와 본문으로 남긴다.

## 정보 구조

| 경로 | 역할 |
| --- | --- |
| `/` | 전체 화면 그래프, 실제 기록과 주제의 연결 탐색 |
| `/projects` | 프로젝트 목록, 제목·태그 검색, 빈도순 태그 필터, 최신순 정렬 |
| `/projects/:slug` | 프로젝트 설명, 이미지, GitHub·서비스 링크 |
| `/books` | 책 목록, 제목·저자 검색, 카테고리 필터, 완독일 최신순 정렬 |
| `/books/:slug` | 책 정보, 독서 시작일·완독일·읽은 곳, 카테고리 필터·저자 검색 링크, 별점, 한 줄 감상, 상세 감상 |
| `/courses` | 강의 기록 목록, 제목 검색, 수강일 최신순 정렬 |
| `/courses/:slug` | 강사·플랫폼, 수강일, 별점, 요약, 상세 기록 |
| `/notes` | 노트 목록, 제목·태그 검색, 정리일 최신순 정렬 |
| `/notes/:slug` | 정리일, 요약, 본문, 태그 |

영화 목록과 상세 화면은 강의 기록으로 대체한다. 기존 프로젝트와 책 콘텐츠는 유지하며, 강의 기록과 노트는 확인된 실제 기록을 표시하고 기록이 없으면 빈 목록을 표시한다.

홈은 전역 헤더 아래의 남은 화면 전체를 가장자리까지 채우는 그래프 캔버스다. 소개 문구·목차·검색 입력·분류별 미리보기·최근 기록 목록·푸터는 홈에 표시하지 않는다. 중앙에는 다른 노드보다 큰 따뜻한 흰색 별 ‘나’를 두고, 주변에 네 기본 분류의 별자리를 비대칭으로 배치한다. 기록을 밝은 별, 기본 분류와 주제를 주황색 별로 표시하고 실제 연결을 가는 선으로 표현한다. 기본 화면의 글자는 ‘나’와 분류·주요 주제·일부 기록 이름으로 제한하며, 선택하거나 초점을 옮긴 노드의 이름은 확인할 수 있어야 한다. 어두운 배경의 작은 장식 별에는 관계를 나타내는 선이나 이름을 붙이지 않는다.

그래프에는 프로젝트·책·강의 기록·노트의 기본 분류 노드 네 개를 항상 포함한다. 중앙의 ‘나’는 네 기본 분류에만 가는 선으로 연결하고 기록이나 주제에는 직접 연결하지 않으며, 이 구조 연결은 각 분류의 작성글 수에 포함하지 않는다. 현재 등록된 실제 작성글을 각각 한 기록 노드로 만들고 종류에 맞는 기본 분류에 한 번씩 자동으로 연결한다. 글이 없는 분류도 기본 노드를 유지하며 예시 글이나 가상 연결을 채우지 않는다. 프로젝트·노트의 실제 태그와 책의 등록 카테고리는 별도의 주제 노드로 만들고 해당 기록과 연결한다. 같은 기록에서 중복된 태그는 한 번만 연결하며, 태그가 없는 기록도 해당 기본 분류에 연결한다. 강의 플랫폼·본문·서로 비슷한 제목으로 관계를 추정하지 않으며, 기록 사이에 근거 없는 선을 추가하지 않는다. 데이터 증가를 보여주는 디자인 시안의 예시 기록은 앱 데이터에 포함하지 않는다.

기본 분류나 주제를 클릭하거나 Enter·Space로 선택하면 직접 연결된 기록과 선을 강조하고 관련 기록의 이름을 표시하며, 다른 연결은 낮은 대비로 유지한다. 같은 노드를 다시 선택하거나 빈 배경을 클릭하거나 Escape를 누르면 선택을 해제한다. 기록 노드는 포인터를 올리거나 키보드 초점을 옮기면 이름을 표시하며, 클릭하거나 Enter를 누르면 해당 상세 화면으로 바로 이동한다. 기존 홈의 `q` URL 매개변수는 그래프에 포함할 기록의 검색 조건으로 유지하며, `kind`는 기본 분류를, `tag`는 주제를 선택한 상태로 연다. 분류·주제 선택만으로 다른 기록을 그래프에서 제거하거나 다른 기록으로 채우지 않는다. ‘나’에 포인터나 키보드 초점을 옮기면 네 기본 분류와의 연결을 강조하고, 클릭하거나 Enter·Space를 누르면 `kind`·`tag` 선택을 해제하고 `q`를 유지한 채 전체 구도로 돌아간다.

캔버스는 드래그·방향키로 이동하고 휠·확대/축소 버튼으로 크기를 조절하며, 전체 보기 버튼으로 기록 전체가 보이는 구도로 복원한다. 분류나 주제를 선택하면 직접 연결된 기록이 화면에 들어오도록 중앙을 맞추고 최대 4배까지 확대하며, 선택 해제는 강조만 없애고 전체 보기 버튼 또는 0키로 전체 구도를 복원한다. 모바일은 터치 드래그와 두 손가락 확대/축소를 지원한다. 노드는 이름과 역할을 제공하고 키보드로 초점을 옮겨 선택할 수 있어야 한다. 노드 배치는 안정적으로 유지하며 움직임 줄이기 설정에서는 장식 움직임을 사용하지 않는다.

홈에는 검색 입력을 두지 않는다. 상단 검색 버튼도 홈에서는 표시하지 않고 전용 목록에서는 현재 검색 입력에 초점을 옮기며 상세 화면에서는 같은 종류의 목록으로 이동한 뒤 검색 입력에 초점을 옮긴다.

화면은 스플릿 콘트라스트 디자인을 사용한다. 전용 목록과 상세 화면은 어두운 상단 내비게이션·소개 영역, 밝은 라이트 테마 콘텐츠 영역과 주황색 포인트로 구성한다. 데스크톱은 상단 가로 내비게이션, 모바일은 같은 메뉴를 펼치는 버튼을 사용한다. 테마는 시스템 설정을 초기값으로 삼고 사용자의 선택을 브라우저에 저장한다. 다크 테마에서는 콘텐츠 영역도 어두운 표면으로 전환한다. 홈의 그래프 캔버스는 테마 선택과 관계없이 어두운 우주 배경을 유지하며 메이플스토리 서체와 주황색 포인트를 공유한다.

프로젝트·책·강의·노트의 전용 목록은 같은 카드·검색·상세 제목 스타일을 공유한다. 프로젝트 카드는 카드 전체를 눌러 상세 화면으로 이동한다. 프로젝트 목록은 검색창 아래에 전체 프로젝트를 기준으로 집계한 상위 20개 태그와 기록 수를 빈도순으로 표시한다. 태그 선택은 `tag` 매개변수의 정확한 일치 필터를 사용하고 제목·태그의 `q` 검색과 함께 적용한다. 책 목록은 데스크톱 4열·태블릿 3열·모바일 2열이며 제목·저자 검색과 카테고리 필터를 함께 사용할 수 있다. 세로형 책 표지는 잘리지 않도록 전체를 표시하고 여백을 둔다. 모든 화면의 제목·본문·브랜드·코드 표시는 메이플스토리 서체로 통일한다. 전용 목록과 상세 화면의 상단 책상 배경은 별도로 생성한 장식용 이미지이며 콘텐츠의 실제 프로젝트·책 이미지와 구분한다.

서체 저작권 안내는 전용 목록과 상세 화면의 푸터에서 제공한다. 짧은 페이지에서는 화면 하단에 배치하고 긴 페이지에서는 본문 뒤에 이어지며, 콘텐츠를 덮지 않는다. 홈에서는 그래프 캔버스의 보조 링크로 같은 안내에 접근할 수 있다.

## 콘텐츠 계약

### 공통 상세 본문

- 프로젝트 `description`, 책·강의 `body`, 노트 본문은 공통 Markdown 표시 방식을 사용한다. 제목, 한 줄 요약과 메타데이터는 일반 텍스트다.
- 소제목, 강조, 목록, 인용문, 링크, 코드 블록, 표, 체크리스트와 이중 물결표(`~~`) 취소선을 지원한다. 단일 물결표는 일반 문자로 유지하며 HTML 태그는 지원하지 않는다.
- 빈 줄은 문단을 구분하고 단일 줄바꿈은 같은 문단으로 이어진다. 명시적인 줄바꿈은 Markdown의 줄 끝 공백 두 개 또는 역슬래시로 작성한다.
- 프로젝트·책·강의 본문은 기존 `static-data.ts`의 여러 줄 문자열에, 노트는 기존 `content/notes/*.md`에 작성한다. 각 본문 글자 수 제한에는 Markdown 원문을 적용한다.
- 기존 콘텐츠를 Markdown으로 정돈할 때는 문구와 메타데이터를 보존한다.

### 프로젝트

- 영문 소문자·숫자·하이픈으로 구성된 고유 slug
- 제목 120자, 한 줄 설명 300자, 상세 설명 2,000자 이내
- 선택적인 썸네일 1개와 스크린샷 0~6개. 이미지가 있으면 대체 텍스트 필수
- 이미지의 `url`은 상세·확대 보기용 원본이며, 선택적인 `sources`에 실제 픽셀 너비(`width`)와 URL을 등록할 수 있다. 목록·상세·확대 보기는 같은 후보를 전달하고 브라우저가 표시 크기와 화면의 픽셀 밀도에 맞는 파일을 선택한다. 후보가 없으면 기존 단일 이미지를 그대로 사용한다.
- 프로젝트 이미지 후보 매핑은 `src/lib/content/project-image-sources.ts`에서 관리한다. 상세·확대 보기에서는 `scale-down`으로 원본 비율을 유지하며 브라우저의 원본 크기(CSS 픽셀 기준)를 넘겨 확대하지 않는다.
- 이미지가 아직 없으면 목록과 상세 화면에 미첨부 안내 표시
- 선택적인 GitHub URL과 서비스 URL
- 프로젝트 성격을 나타내는 태그 0~8개
- 선택적인 프로젝트 시작일과 종료일. 확인된 경우 화면에 진행 기간으로 표시
- 공개 시각과 생성·수정 시각

### 책 기록

- `book` 종류와 고유 slug
- 제목과 저자, 완독일(`consumedOn`)
- 선택적인 독서 시작일(`startedOn`). 완독일보다 늦을 수 없으며, 미입력 시 상세 화면에 `미기록` 표시
- 선택적인 읽은 곳(`readingSource`), 120자 이내. 직접 소장 여부나 이용한 독서 플랫폼을 기록
- 선택적인 카테고리 1개, 30자 이내. 예: `고전소설`
- 1~5 범위의 정수 단위 별점
- 한 줄 감상 300자, 상세 감상 2,000자 이내
- 표지 이미지와 대체 텍스트
- 공개일

책 목록은 제목 또는 저자를 `q`로 검색하며 저자 선택 드롭다운은 두지 않는다. 카테고리 선택지는 등록된 전체 책에서 중복 없이 구성한다. 검색창 아래에는 실제 카테고리를 태그로 표시하며 전체 책을 기준으로 집계한 빈도 내림차순·동률 한국어 이름순 상위 20개와 기록 수를 표시한다. 태그를 누르면 `category`의 정확한 일치 필터를 적용하고 기존 `q`를 유지한다. 제목·저자 검색과 카테고리 필터를 함께 사용할 수 있으며 선택한 조건은 `q`, `category` URL 매개변수로 유지한다. 초기화는 모든 조건을 해제한다. 카테고리가 없는 책도 전체 목록과 저자 검색에서 조회할 수 있다. 상세 화면의 저자 링크는 `/books?q=저자`로 연결한다. 이전 `author` URL은 `q`가 없으면 해당 값을 검색어로 사용하는 방식으로 호환한다.

### 강의 기록

- `course` 종류와 고유 slug
- 제목, 강사, 수강일과 선택적인 플랫폼
- 1~5 범위의 정수 단위 별점
- 요약 300자, 상세 기록 2,000자 이내
- 선택적인 대표 이미지. 이미지가 있으면 대체 텍스트 필수
- 공개일

### 노트

- 고유 slug와 제목
- 정리일(`studiedOn`), 요약, 본문 20,000자 이내
- 주제 태그 0~8개, 각 30자 이내
- 별점 없이 텍스트 중심으로 구성하며, 이해를 돕는 설명 이미지는 본문에 대체 텍스트와 함께 첨부할 수 있다.
- 공개일

## 실행 및 배포 구조

- React 19, TypeScript, Vite 기반의 정적 SPA다. 서버 런타임과 브라우저 관리자 화면은 사용하지 않는다.
- React Router의 브라우저 라우팅으로 목록과 상세 화면을 전환하며, 검색은 브라우저에서 수행한다.
- `pnpm build`는 `dist/`를 생성하고 목록·등록된 상세 경로의 `index.html` 셸과 `404.html`을 만든다. GitHub Pages에서 유효한 상세 URL의 직접 접근과 새로고침을 지원한다.
- 상세 본문은 브라우저에서 렌더링한다. 경로별 HTML 셸은 본문을 미리 렌더링하는 SSG나 페이지별 검색 엔진 HTML 프리렌더링이 아니다.
- 배포 기준 경로는 `VITE_BASE_PATH`로 설정한다. 기본값은 `/`이며 저장소 Pages에 `/y-brary/`로 게시한다면 `VITE_BASE_PATH=/y-brary/ pnpm build`를 사용한다.
- 메타데이터 기준 주소는 `VITE_SITE_URL`로 설정하며 기본값은 `http://localhost:3001`이다.
- 링크 공유 미리보기는 메인 화면 캡처를 공통 이미지로 사용한다. 홈과 목록에는 사이트 소개를, 상세 경로에는 해당 기록의 제목과 요약을 정적 HTML의 Open Graph·Twitter 메타데이터로 제공한다. 브라우저 탭에는 YBrary의 주황색 Y 파비콘을 표시한다.
- GitHub Pages는 `main`에 push하면 린트·타입 검사·테스트·빌드가 통과한 뒤 자동 배포한다. `workflow_dispatch`를 통한 수동 실행도 지원한다.

## 데이터 및 공개 정책

- 현재 앱은 프로젝트·책·강의를 `src/lib/content/static-data.ts`에서, 노트를 `content/notes/*.md`의 YAML frontmatter와 Markdown 본문에서 읽어 빌드에 포함한다.
- 샘플 레코드는 앱에 포함하지 않는다.
- 정적 콘텐츠는 Zod 스키마를 통과해야 빌드할 수 있다.
- 이미지 원본과 공개 권리를 확인한 뒤 배포 자산에 추가한다.
- Supabase 스키마와 원격 게시 도구는 기존 데이터베이스 전환 준비물이며 현재 앱 런타임에서는 사용하지 않는다. 기존 프로젝트·`book`/`film` 계약을 유지하므로 강의 기록·노트를 등록하는 도구로 사용할 수 없다.
- 검색 엔진 색인은 `VITE_ENABLE_INDEXING=true`로 명시하기 전까지 차단한다.

## 콘텐츠 운영 원칙

- 사용자에게 확인받지 않은 개인 프로젝트·독서·수강·학습 사실이나 개인적인 견해, 날짜·별점·본문을 만들어 게시하지 않는다.
- 책 표지, 강의 이미지, 프로젝트 스크린샷은 공개 사용 권한과 출처를 확인한다.
- 원격 게시·수정·삭제 전 정확한 콘텐츠의 미리보기를 사용자에게 보여주고 명시적인 승인을 받는다. 기존 원격 게시 도구는 `content:preview`로 검증하며, 현재 정적 앱 콘텐츠는 로컬 화면에서 확인하고 자동 배포되는 `main`에 push하기 전에 승인받는다.
- 원본 이미지와 draft는 로컬 작업물이며 콘텐츠 이미지는 최적화된 WebP로 배포한다. 공유 미리보기에는 호환성을 위한 최적화된 JPEG, 파비콘에는 SVG와 PNG를 사용한다.
