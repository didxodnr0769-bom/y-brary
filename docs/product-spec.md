# YBrary 제품 명세

## 목적

YBrary는 개인 사이드 프로젝트, 책과 강의 기록, 학습 내용을 하나의 공개 아카이브로 정리한다. 프로젝트는 결과물을 빠르게 보여주고, 책과 강의는 경험과 평가를 남기며, 학습 정리는 배운 개념을 태그와 본문으로 정리한다.

## 정보 구조

| 경로 | 역할 |
| --- | --- |
| `/` | 모든 종류의 통합 기록, 제목·태그·저자·카테고리·플랫폼 검색, 게시일 최신순 정렬 |
| `/projects` | 프로젝트 목록, 제목·태그 검색, 최신순 정렬 |
| `/projects/:slug` | 프로젝트 설명, 이미지, GitHub·서비스 링크 |
| `/books` | 책 목록, 제목 검색, 카테고리·저자 필터, 완독일 최신순 정렬 |
| `/books/:slug` | 책 정보, 독서 시작일·완독일·읽은 곳, 카테고리·저자별 목록 링크, 별점, 한 줄 감상, 상세 감상 |
| `/courses` | 강의 기록 목록, 제목 검색, 수강일 최신순 정렬 |
| `/courses/:slug` | 강사·플랫폼, 수강일, 별점, 요약, 상세 기록 |
| `/notes` | 학습 정리 목록, 제목·태그 검색, 정리일 최신순 정렬 |
| `/notes/:slug` | 정리일, 요약, 본문, 태그 |

영화 목록과 상세 화면은 강의 기록으로 대체한다. 기존 프로젝트와 책 콘텐츠는 유지하며, 강의 기록과 학습 정리는 확인된 실제 기록이 등록되기 전까지 빈 목록을 표시한다.

홈은 프로젝트·책·강의·학습 정리를 공개일(`publishedAt`) 내림차순으로 섞어 보여준다. 같은 공개일에는 종류와 레코드 ID로 일정하게 정렬한다. 각 카드는 같은 16:10 이미지 영역과 종류·공개일·제목·요약을 사용하며, 세로형 책 표지는 높이에 맞춰 전체를 표시하고 좌우 여백을 둔다. 프로젝트의 진행 기간은 목록 카드에서 생략하고 상세 화면에서 확인한다.

데스크톱은 고정 사이드바, 모바일은 상단 헤더와 열고 닫는 내비게이션을 사용한다. 테마는 시스템 설정을 초기값으로 삼고 사용자의 선택을 브라우저에 저장한다.

서체 저작권 안내는 본문과 구분된 푸터에 표시한다. 짧은 페이지에서는 화면 하단에 배치하고 긴 페이지에서는 본문 뒤에 이어지며, 콘텐츠를 덮지 않는다.

## 콘텐츠 계약

### 프로젝트

- 영문 소문자·숫자·하이픈으로 구성된 고유 slug
- 제목 120자, 한 줄 설명 300자, 상세 설명 2,000자 이내
- 선택적인 썸네일 1개와 스크린샷 0~6개. 이미지가 있으면 대체 텍스트 필수
- 이미지가 아직 없으면 목록과 상세 화면에 미첨부 안내 표시
- 선택적인 GitHub URL과 서비스 URL
- 프로젝트 성격을 나타내는 태그 0~8개
- 선택적인 프로젝트 시작일과 종료일. 확인된 경우 화면에 진행 기간으로 표시
- 공개 시각과 생성·수정 시각

### 책 기록

- `book` 종류와 고유 slug
- 제목과 저자, 완독일(`consumedOn`)
- 선택적인 독서 시작일(`startedOn`). 완독일보다 늦을 수 없으며, 미입력 시 상세 화면에 `미기록` 표시
- 선택적인 읽은 곳(`readingSource`), 120자 이내. 직접 소장 여부나 이용한 독서 플랫폼을 기록
- 선택적인 카테고리 1개, 30자 이내. 예: `고전소설`
- 1~5 범위의 정수 단위 별점
- 한 줄 감상 300자, 상세 감상 2,000자 이내
- 표지 이미지와 대체 텍스트
- 공개일

책 목록의 카테고리·저자 선택지는 등록된 전체 책에서 중복 없이 구성한다. 제목 검색과 두 필터를 함께 적용할 수 있으며, 선택한 조건은 `q`, `category`, `author` URL 매개변수로 유지한다. 초기화는 모든 조건을 해제한다. 카테고리가 없는 책도 전체 목록과 저자별 목록에서 조회할 수 있다.

### 강의 기록

- `course` 종류와 고유 slug
- 제목, 강사, 수강일과 선택적인 플랫폼
- 1~5 범위의 정수 단위 별점
- 요약 300자, 상세 기록 2,000자 이내
- 선택적인 대표 이미지. 이미지가 있으면 대체 텍스트 필수
- 공개일

### 학습 정리

- 고유 slug와 제목
- 정리일(`studiedOn`), 요약, 본문 20,000자 이내
- 학습 주제 태그 0~8개, 각 30자 이내
- 이미지와 별점 없이 텍스트 중심으로 구성
- 공개일

## 실행 및 배포 구조

- React 19, TypeScript, Vite 기반의 정적 SPA다. 서버 런타임과 브라우저 관리자 화면은 사용하지 않는다.
- React Router의 브라우저 라우팅으로 목록과 상세 화면을 전환하며, 검색은 브라우저에서 수행한다.
- `pnpm build`는 `dist/`를 생성하고 목록·등록된 상세 경로의 `index.html` 셸과 `404.html`을 만든다. GitHub Pages에서 유효한 상세 URL의 직접 접근과 새로고침을 지원한다.
- 상세 본문은 브라우저에서 렌더링한다. 경로별 HTML 셸은 본문을 미리 렌더링하는 SSG나 페이지별 검색 엔진 HTML 프리렌더링이 아니다.
- 배포 기준 경로는 `VITE_BASE_PATH`로 설정한다. 기본값은 `/`이며 저장소 Pages에 `/y-brary/`로 게시한다면 `VITE_BASE_PATH=/y-brary/ pnpm build`를 사용한다.
- 메타데이터 기준 주소는 `VITE_SITE_URL`로 설정하며 기본값은 `http://localhost:3001`이다.
- GitHub Pages는 `main`에 push하면 린트·타입 검사·테스트·빌드가 통과한 뒤 자동 배포한다. `workflow_dispatch`를 통한 수동 실행도 지원한다.

## 데이터 및 공개 정책

- 현재 앱은 프로젝트·책·강의를 `src/lib/content/static-data.ts`에서, 학습 정리를 `content/notes/*.md`의 YAML frontmatter와 Markdown 본문에서 읽어 빌드에 포함한다.
- 샘플 레코드는 앱에 포함하지 않는다.
- 정적 콘텐츠는 Zod 스키마를 통과해야 빌드할 수 있다.
- 이미지 원본과 공개 권리를 확인한 뒤 배포 자산에 추가한다.
- Supabase 스키마와 원격 게시 도구는 기존 데이터베이스 전환 준비물이며 현재 앱 런타임에서는 사용하지 않는다. 기존 프로젝트·`book`/`film` 계약을 유지하므로 강의 기록·학습 정리를 등록하는 도구로 사용할 수 없다.
- 검색 엔진 색인은 `VITE_ENABLE_INDEXING=true`로 명시하기 전까지 차단한다.

## 콘텐츠 운영 원칙

- 사용자에게 확인받지 않은 개인 프로젝트·독서·수강·학습 사실이나 날짜·별점·본문을 만들어 게시하지 않는다.
- 책 표지, 강의 이미지, 프로젝트 스크린샷은 공개 사용 권한과 출처를 확인한다.
- 원격 게시·수정·삭제 전 정확한 콘텐츠의 미리보기를 사용자에게 보여주고 명시적인 승인을 받는다. 기존 원격 게시 도구는 `content:preview`로 검증하며, 현재 정적 앱 콘텐츠는 로컬 화면에서 확인하고 자동 배포되는 `main`에 push하기 전에 승인받는다.
- 원본 이미지와 draft는 로컬 작업물이며, 배포 자산에는 최적화된 WebP만 사용한다.

## 현재 범위 밖

- 방문자 회원가입, 댓글, 좋아요
- 브라우저 기반 관리자 화면과 직접 편집
- 상세 설명 전문 검색과 추천
- 원격 Supabase 프로젝트 자동 생성
- 기존 Supabase 스키마·원격 게시 도구의 강의 기록·학습 정리 계약 전환

## 남은 외부 결정

- 데이터베이스 전환이 필요해지는 시점과 Supabase 조직·요금제·프로젝트 리전
- 배포 호스트와 운영 도메인
- 실제 첫 책·강의 기록, 학습 정리와 YBrary 프로젝트 이미지
- 검색 엔진 색인을 켤 시점
