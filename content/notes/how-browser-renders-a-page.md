브라우저에 사이트 주소를 입력하면 잠시 뒤 화면이 나타난다. 서버에서 받은 파일은 어떻게 우리가 보고 누를 수 있는 화면이 될까?

이 글에서는 브라우저가 페이지를 요청하고, 받은 HTML과 CSS를 바탕으로 화면을 만드는 과정을 살펴본다. 주소를 찾고 연결하는 과정은 여기서 자세히 다루지 않는다.

```text
주소 입력 → 서버에 페이지 요청 → HTML 응답
                               ↓
                  HTML을 읽고 필요한 파일 요청
                               ↓
               DOM 생성 + CSS 적용 → 화면 그리기
                               ↑
                    JavaScript로 내용 변경 가능
```

![HTML에서 DOM을 만들고 CSS를 적용한 뒤 레이아웃, 페인트, 합성을 거쳐 화면에 표시한다. JavaScript는 DOM을 바꿀 수 있다.](/images/notes/browser-rendering/rendering-flow.webp)

이 흐름은 이해를 돕기 위한 그림이다. 실제 브라우저에서는 파일 다운로드, 해석, 화면 표시가 일부 겹쳐 진행될 수 있다.

## 1. 브라우저는 페이지를 요청한다

브라우저는 서버에 HTTP 요청을 보내 페이지를 요청한다. 서버는 요청에 대한 HTTP 응답을 보내며, 응답 본문에 HTML이 들어갈 수 있다.

```text
브라우저 → 서버: 페이지를 보내주세요
브라우저 ← 서버: 요청 결과와 HTML
```

브라우저는 HTML을 읽다가 CSS, JavaScript, 이미지처럼 필요한 자원을 발견하면 추가로 요청할 수 있다. 이미 저장된 자원을 사용하는 경우도 있다.

HTML과 CSS, JavaScript는 각각 다른 역할을 맡는다.

| 구성 요소 | 역할 |
| --- | --- |
| HTML | 제목, 문단, 버튼 등 문서의 구조와 내용을 표현한다. |
| CSS | 색상, 크기, 간격, 배치 등 요소의 모양을 정한다. |
| JavaScript | 사용자 입력을 처리하거나 문서의 내용과 스타일을 바꿀 수 있다. |

## 2. HTML을 읽어 DOM을 만든다

HTML은 문서를 표현하는 마크업 텍스트다. 브라우저는 HTML을 해석해 메모리에 **DOM(Document Object Model)이라는** 문서 구조를 만든다.

예를 들어 다음 HTML을 보자.

```html
<body>
  <h1>안녕하세요</h1>
  <p>반갑습니다.</p>
  <button>눌러보세요</button>
</body>
```

브라우저가 만든 DOM의 일부를 단순하게 나타내면 다음과 같다.

```text
body
├─ h1
│  └─ 안녕하세요
├─ p
│  └─ 반갑습니다.
└─ button
   └─ 눌러보세요
```

DOM은 요소와 텍스트를 트리 형태로 표현한다. `body` 안에 `h1`, `p`, `button`이 들어 있는 부모와 자식 관계도 담는다.

**HTML은 전달받은 텍스트이고, DOM은 브라우저가 해석해 만든 현재 문서 구조다.** JavaScript는 DOM을 통해 요소를 찾고 내용을 바꿀 수 있다. 브라우저가 HTML을 해석하면서 빠진 구조를 보완하기도 하므로, 둘이 언제나 똑같은 모양은 아니다.

### 요소 탭에서 보는 것은 무엇일까?

브라우저 개발자 도구의 **요소(Elements) 탭**은 현재 DOM을 HTML과 비슷한 형태로 보여준다. JavaScript가 요소를 추가하거나 글자를 바꾸면 그 변화도 볼 수 있다.

반면 **페이지 소스 보기**에서는 일반적으로 서버에서 받은 HTML 소스를 확인한다. 처음 받은 HTML과 현재 DOM이 다를 수 있는 이유다.

요소 탭에서 직접 글자를 고치면 화면에서 결과를 확인할 수 있다. 이때 바뀌는 것은 브라우저의 현재 문서이며, 프로젝트의 원본 파일은 수정되지 않는다. 새로고침하면 보통 변경 내용은 사라진다.

## 3. CSS를 적용해 모양을 정한다

HTML에 연결된 CSS에 다음 규칙이 있다고 해보자.

```css
h1 {
  color: blue;
  font-size: 32px;
}

button {
  background: black;
  color: white;
  padding: 12px;
}
```

브라우저는 CSS 규칙을 해석하고 DOM의 각 요소에 적용할 스타일을 계산한다. 제목은 파란색 글자로, 버튼은 검은 배경과 흰 글자로 표시하도록 정하는 식이다.

여러 규칙이 같은 요소를 가리킬 수도 있다. 브라우저는 규칙의 중요도, 선택자의 구체성, 작성 순서 등을 고려해 최종 값을 결정한다. 이를 **캐스케이드**라고 한다. 직접 지정하지 않은 값에는 상속된 값이나 브라우저 기본 스타일 등이 사용될 수 있다.

## 4. 위치를 계산하고 화면을 그린다

DOM과 적용할 스타일이 준비되면 브라우저는 요소를 어디에 얼마나 크게 놓을지 계산한다. 이 과정을 **레이아웃(layout)이라고** 한다.

제목을 어느 위치에 놓을지, 문단의 줄이 어디서 바뀔지, 버튼이 얼마나 공간을 차지할지 정하는 일이다. 화면 크기, 글자 크기, 여백, Flexbox나 Grid 같은 배치 방식이 계산에 영향을 준다.

그다음에는 배경, 테두리, 글자 등을 그리는 **페인트(paint)** 작업이 이어진다. 브라우저는 필요에 따라 화면의 일부를 별도 레이어로 처리하고, 그 결과를 순서에 맞게 겹쳐 최종 화면을 보여준다. 이를 **합성(compositing)이라고** 한다.

```text
레이아웃: 요소의 위치와 크기를 계산한다.
페인트:   배경, 글자, 테두리 등을 그린다.
합성:     필요한 레이어들을 겹쳐 화면에 표시한다.
```

합성한 결과는 사용자에게 하나의 화면으로 보인다. 브라우저 내부에서는 갱신을 위해 레이어를 따로 유지할 수 있다. 모든 HTML 요소가 각각 별도 레이어가 되는 것은 아니며, 실제 처리 방식은 브라우저와 상황에 따라 달라진다.

## 5. JavaScript가 화면을 바꾸면?

JavaScript는 DOM의 요소를 찾아 내용을 바꿀 수 있다. 다음은 버튼을 누르면 제목을 바꾸는 예시다.

```js
const button = document.querySelector("button");
const title = document.querySelector("h1");

button.addEventListener("click", () => {
  title.textContent = "버튼을 눌렀어요!";
});
```

![처음 받은 HTML은 그대로이고, 버튼 클릭으로 JavaScript가 DOM의 제목을 바꾸면 화면이 갱신된다.](/images/notes/browser-rendering/dom-update.webp)

사용자가 버튼을 누르면 JavaScript가 제목의 DOM 내용을 바꾼다. 브라우저는 그 변화에 맞춰 필요한 작업을 다시 수행하고 바뀐 화면을 보여준다.

```text
버튼 클릭 → JavaScript 실행 → DOM 변경 → 화면 갱신
```

변경 내용에 따라 다시 수행하는 작업은 달라진다. 글자 내용이 바뀌어 크기나 배치에 영향을 주면 레이아웃을 다시 계산할 수 있다. 색상만 바뀐다면 일반적으로 위치와 크기를 다시 계산할 필요 없이 그리기 작업을 다시 수행한다.

이때 바뀌는 것은 브라우저에 있는 DOM이다. 처음 서버에서 받은 HTML 파일이 자동으로 수정되는 것은 아니다.

## 6. JavaScript는 언제 실행될까?

브라우저가 HTML을 읽다가 일반적인 외부 `<script>`를 만나면, 스크립트를 가져와 실행하는 동안 HTML 해석이 멈출 수 있다.

외부 스크립트에 `defer`를 사용하면 HTML을 읽는 동안 파일을 내려받고, HTML 해석이 끝난 뒤 실행한다.

```html
<script src="app.js" defer></script>
```

따라서 스크립트를 불러오는 방식도 HTML 해석과 화면이 표시되는 시점에 영향을 줄 수 있다.

React처럼 JavaScript를 활용하는 앱은 간단한 HTML을 받은 뒤 JavaScript를 실행해 화면을 구성할 수 있다. 서버가 미리 만들어진 HTML을 보내는 방식도 있다. 어떤 방식을 사용하든 브라우저는 현재 문서와 스타일을 바탕으로 화면을 계산하고 표시한다.
